## Summary

A brief processor-side blip caused payments-api to retry aggressively with no
jitter. The synchronized retries pushed request volume past the contracted
rate limit, and the processor began returning HTTP 429 (`ERR_7702`) to
everything, including first attempts.

## Symptoms

- HTTP 429 / ERR_7702 from processor-api on 60% of calls
- payments-api error rate 22%
- Outbound request rate 3.4x baseline with a strong 15-second periodicity

## Root cause

Fixed-interval retries with no jitter and no circuit breaker turned a two-minute
upstream blip into a 50-minute self-inflicted outage.

## Remediation

1. [diagnose] Correlate outbound request rate against 429 responses — @dan
2. [mitigate] Drop the retry budget from 5 attempts to 1 via feature flag — @dan (outcome: outbound rate fell below the limit within 90 seconds; 429s stopped)
3. [fix] Ship exponential backoff with full jitter and a circuit breaker — @lena

## Prevention

- Client-side rate limiter pinned below the contracted ceiling
